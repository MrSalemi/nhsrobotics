# Part 1: How it works

Read this part when you get stuck. It has the answer to almost every question you will have.

## Today you need one cable and nothing else

No WiFi. No browser. No controller. No Bluetooth pairing.

That is deliberate. Every one of those things is a place a first day can go wrong, and none of them teach you anything about Python. Today it is the robot, a USB cable, and code you typed. Everything else arrives later, once you already know what a working program looks like.

## You type the code yourself

Your Python file is mostly empty. That is on purpose.

Every line you need is printed in Part 2 of this guide, and you type it into the file by hand. Typing it is the point. It is how the shape of Python gets into your hands instead of just past your eyes.

You will make mistakes doing this. Everyone does. Finding them is most of what programming is.

## Blocks

A program is not just a list of lines. Lines get grouped, and a group of lines is called a block.

Here is the idea without any robot in it:

```
if it is raining:
    take an umbrella
    wear boots
go to school
```

"Take an umbrella" and "wear boots" are a block. They belong to the rain. If it is not raining you skip both of them. "Go to school" is not in the block, so it happens either way.

Python shows blocks by pushing them to the right:

- A line that ends with a colon starts a block.
- The lines pushed to the right below it are the block.
- The first line that comes back to the left ends the block.

**Thonny does the pushing for you.** End a line with a colon, press Enter, and the cursor is already sitting where the block starts. It keeps you there, line after line, until you tell it otherwise. To come back out of a block, press Backspace once.

So when you type code out of this guide, you mostly do not have to think about the spacing at all. When you do have to think about it: four spaces per level, never a tab.

## Setting up

The first thing your program does is build what it needs. These three lines are already in your file:

```
alvik = ArduinoAlvik()
alvik.begin()
sb = SuperBot(alvik)
```

Each of those lines makes one thing and gives it a name. Programmers call those things objects. An object is a bundle of information plus the commands that go with it.

- `alvik` is the robot itself. `ArduinoAlvik()` builds it and `begin()` starts it running.
- `sb` is a SuperBot. Think of it as an Iron Man suit for the Alvik. The robot climbs inside and comes out able to do things it cannot do on its own. This class built the suit. Every project puts it on, and each project uses a few more of its powers. Today you use exactly one.

The order matters. `alvik` has to exist *and* be running before the third line, because that line is handed `alvik` to work with.

You get these for free today. In P01 you type them yourself.

When you run the program, the Shell prints a version number for each part of the suit as it loads. That is normal. It is how you know which version of the code your robot is running.

## The main loop

Real robots do not run once and stop. They loop. They do their job over and over, hundreds of times a second.

Your loop is already in the file:

```
while not sb.held('cancel'):
```

That line ends in a colon, so everything below it that is pushed to the right is the loop's block. It runs again and again.

That line is also your stop button. Touch Cancel on the robot — the X pad — and the loop ends on its own. You do not need Thonny's Stop button.

`held()` answers one question: is that pad down right now? The robot's own touch pads are `'up'`, `'down'`, `'left'`, `'right'`, `'ok'` and `'cancel'`.

## Mixing colors

Your robot has two RGB LEDs on its top board, one on each side of the touch buttons. In code they are `alvik.left_led` and `alvik.right_led`.

Each one mixes red, green, and blue. You pass a 1 to turn a color on and a 0 to turn it off. These examples all use the left LED. The right one works exactly the same way.

```
alvik.left_led.set_color(1, 0, 0)   # red
alvik.left_led.set_color(0, 1, 0)   # green
alvik.left_led.set_color(0, 0, 1)   # blue
alvik.left_led.set_color(1, 1, 1)   # white, all three at once
alvik.left_led.set_color(0, 0, 0)   # off
```

Look at that list again. There is no yellow in it.

That is because yellow is not one of the three. You make it, by turning red and green on at the same time and letting your eye do the mixing. Two colors at once always make a new one — red plus blue is magenta, green plus blue is cyan. You will want those for the flex.

## Waiting on purpose

The loop runs faster than you can see. Without a pause, all four steps of your pattern would happen in a fraction of a second and the lights would look like one muddy color that never changes.

So you slow it down:

```
time.sleep(0.5)
```

That waits half a second and then carries on. Each step of your pattern gets one, which is why the pattern is visible at all.

## The finally block

At the bottom of your file is a `finally:` block.

Code inside `finally` always runs. It runs when the program ends normally. It runs when you hit Stop. It runs even if your code crashes.

That matters. Without it the robot freezes in whatever state it was in, lights stuck on. In later projects, with motors, it would be wheels stuck spinning.

So every program in this class cleans up in `finally`.

One line is already written for you: `alvik.stop()`. Always call it, in every project. It shuts down the robot software and frees the WiFi network. Skip it and the robot can hang, and then you have to restart it to get going again.

# Part 2: Do the work

## Step 1: Set up

1. Turn on your Alvik robot.
2. Connect it to your Mac with the USB cable.
3. Open `p00_first_lights.py` in Thonny and save your own copy to the robot, as described at the top of this guide. **Name it** `p00.py`.

Run it before you type anything. You should get version numbers in the Shell and nothing else — no lights, no movement. That means the suit is on and the file is ready for you.

## Step 2: Type in WORK 1

Two lights, two different colors, and a wait so you can see them.

Find the `# WORK 1` comment. Type these lines where the `pass` line is, then delete the `pass` line:

```
alvik.left_led.set_color(1, 0, 0)
alvik.right_led.set_color(0, 1, 0)
time.sleep(0.5)
```

Run it. The left light goes red and the right goes green, and they stay that way until you touch Cancel.

They stay that way because right now that is the whole program. The loop runs it over and over, but every pass sets the same two colors, so nothing appears to change. WORK 2 fixes that.

## Step 3: Type in WORK 2

The swap. Same three lines, two values traded.

Find the `# WORK 2` comment and type these underneath your WORK 1 lines, at the same indent:

```
alvik.left_led.set_color(0, 1, 0)
alvik.right_led.set_color(1, 0, 0)
time.sleep(0.5)
```

Run it. Now the two lights trade places, back and forth, half a second each way.

Nothing new happened here. You wrote the same three lines with different numbers, and the robot did something completely different. That is most of what programming is.

## Step 4: Type in WORK 3

Yellow, and then dark.

There is no yellow setting, so you make one. Red and green together, on both lights.

Find the `# WORK 3` comment and type these under your WORK 2 lines, at the same indent:

```
alvik.left_led.set_color(1, 1, 0)
alvik.right_led.set_color(1, 1, 0)
time.sleep(0.5)

alvik.left_led.set_color(0, 0, 0)
alvik.right_led.set_color(0, 0, 0)
time.sleep(0.5)
```

The last three lines turn everything off and wait again. Without that gap the pattern runs straight into itself and you cannot see where it starts over.

Run it. Red-green, green-red, yellow-yellow, dark — and around again, until you touch Cancel.

## Step 5: Worksheet and check off

One run shows all of it. Plug in, run, and watch the four steps cycle. Touch Cancel to stop.

## FLEX: The A+

This one is not printed anywhere. You work it out.

Add a fourth step to your pattern, in a color that is not red, green, or yellow.

The catch is that you cannot look it up in this guide, because the only colors printed in it are the ones you have already used. You have three switches per light and you have seen what turning two on at once does. Work out a new one and put it in.

Two lights means you can run two different invented colors at the same time. Do that, and make them ones nobody else picks.
