# Part 1: How it works

Read this part when you get stuck. It has the answer to almost every question you will have.

## No gamepad this time

P01 needed WiFi, Chrome, and a paired controller. This one needs none of that. Plug the robot into your Mac with the USB cable and run it.

The Iron Man suit still goes on. Your file starts the same way P01 did:

```
alvik = ArduinoAlvik()
alvik.begin()
sb = SuperBot(alvik)
```

You are also using the same two lights as P01, and the same `set_color(r, g, b)` command, with 0 or 1 for each color. Everything you type comes out of Part 2 of this guide, same as before, and Thonny still does the indenting for you.

## SuperBot's new power

Setting both lights took two lines in P01:

```
alvik.left_led.set_color(1, 0, 0)
alvik.right_led.set_color(1, 0, 0)
```

The suit has a power that does both at once:

```
sb.light_both_leds(1, 0, 0)
```

Same result, one line. It takes the same three numbers `set_color()` does, and it hands them to both lights for you.

That is the second power you have used. The first was `sb.held('cancel')`, which asks whether the Cancel pad on the robot is being touched right now. Every project adds a few more.

## Use functions to make coding easier

A function is a chunk of code somebody already wrote, with a name stuck on it. You do not have to know what is inside it. You say the name, and it runs. That makes it easy to use.

Your microwave has a POPCORN button. Somebody worked out the power level and the timing and hid all of it behind one word. You press POPCORN. You do not press "700 watts for two minutes and fifteen seconds." A function is that button.

To use one, you write its name with parentheses after it. That is called *calling* the function.

Now look at three lines you typed in P01:

```
alvik.begin()                       # wakes the robot up
alvik.left_led.set_color(1, 0, 0)   # sets a light to red
time.sleep(0.5)                     # waits half a second
```

Every one of those is a function. You have been calling them since your first day, and nobody said the word.

The values inside the parentheses are called arguments. They are how you tell the function what you want. `set_color(1, 0, 0)` means red. `set_color(0, 0, 1)` means blue. Same function, different arguments, different result.

Some functions need no arguments. `alvik.begin()` has empty parentheses because there is nothing to tell it.

## How to blink the LEDs

A blink is four steps, in order:

- Turn the lights on.
- Wait.
- Turn the lights off.
- Wait again.

Miss the second wait and there is no blink. The lights go off and instantly back on, far too fast to see. Your eye reads it as dim, steady light.

If we want to blink more than once, we need a way to run that code again. To blink three times, we could write this:

```
# once
sb.light_both_leds(1, 0, 0)   # on, red
time.sleep(0.5)               # wait
sb.light_both_leds(0, 0, 0)   # off
time.sleep(0.5)               # wait
# twice
sb.light_both_leds(1, 0, 0)   # on, red
time.sleep(0.5)               # wait
sb.light_both_leds(0, 0, 0)   # off
time.sleep(0.5)               # wait
# thrice
sb.light_both_leds(1, 0, 0)   # on, red
time.sleep(0.5)               # wait
sb.light_both_leds(0, 0, 0)   # off
time.sleep(0.5)               # wait
```

Obviously, this is a waste of code. It would also be hard to change the color or the timing, because we would have to make the same edit twelve times and hope we did not miss one. And what if we wanted to blink 100 times?

We need a way to run the same code over and over.

## Using a for loop and range

A `for` loop runs a block a set number of times. We tell it how many using `range()`.

To blink three times, we wrap those same four steps in a loop that runs three times:

```
for _ in range(3):
    sb.light_both_leds(1, 0, 0)   # on, red
    time.sleep(0.5)               # wait
    sb.light_both_leds(0, 0, 0)   # off
    time.sleep(0.5)               # wait
```

Twelve lines became four. Change the 3 to a 20 and it blinks twenty times, and you only touched one character. The loop does the counting for you.

The four indented lines are the loop's block, exactly like the blocks you met in P01. That is WORK 1.

## Blink a whole pattern with one line

Even that loop is more typing than it needs to be. Every time you want a blink, you write five lines again.

So I wrapped the whole thing in a function for you. It is near the top of your file, and this one line runs it:

```
blink(3, 0.5, 0.5, 1, 0, 0)
```

Three blinks, half a second on, half a second off, red. One line does everything WORK 1 does by hand.

## Look inside a function

So far every function you called came from somewhere you cannot see. Here is one you can. This is `blink()`, near the top of your file:

```
def blink(blinks, on_time, off_time, red, green, blue):
    for _ in range(blinks):
        sb.light_both_leds(red, green, blue)
        time.sleep(on_time)
        sb.light_both_leds(0, 0, 0)
        time.sleep(off_time)
```

Read it a piece at a time.

`def` is short for define. It means "here is a new function, and here is its name." Those lines do NOT run when Python reads them. They sit there waiting. They only run when something calls `blink(...)`.

The six names in the parentheses are the arguments. You have already met arguments — they are the values you hand a function when you call it. The `def` line is where those values arrive, and these names are what the function calls them once they get there.

They hold nothing until somebody calls `blink()`. When you write `blink(3, 0.5, 0.5, 1, 0, 0)`, Python puts 3 into `blinks`, 0.5 into `on_time`, 0.5 into `off_time`, and 1, 0, 0 into `red`, `green` and `blue`. Then it runs the block underneath using those values.

The indented lines below the `def` are the function's block, the same idea as every other block.

Look at the ladder you now have. `set_color()` sets one light. `sb.light_both_leds()` sets two, and calls `set_color()` twice to do it. `blink()` runs a whole pattern, and calls `sb.light_both_leds()` over and over to do that. Each one wraps up the one below it so you can say more with less typing. Before long you will be writing your own.

## Variables: Storing numbers using names

That `blink(3, 0.5, 0.5, 1, 0, 0)` line works, but look at it. Six bare numbers in a row. Which one is the color? Which is the speed? You have to count positions to find out.

A variable is a name for a value. You write the value once and use the name after that:

```
on_time  = 0.5
off_time = 0.5
red = 1
green = 0
blue = 0

blink(3, on_time, off_time, red, green, blue)
```

Now the line reads like a sentence. And here is the part that matters: change a variable, and the same call does something different. Set `red = 0` and `blue = 1` and that identical `blink(...)` line blinks blue instead of red.

Programmers have a rule about this: never type the same number twice. Name it once instead.

## The show repeats until you touch Cancel

Everything you write sits inside a loop:

```
while not sb.held('cancel'):
```

Read it out loud: while Cancel is NOT held, keep going. So your three light patterns play, then play again, over and over, until you touch the Cancel pad on the robot. No Thonny Stop button needed.

# Part 2: Do the work

## Step 1: Set up

1. Turn on your Alvik robot.
2. Connect it to your Mac with the USB cable.
3. Open `p02_flashing_lights.py` in Thonny and save your own copy to the robot, as described at the top of this guide.

Run it before you type anything. You should get version numbers in the Shell and nothing else. That means the suit is on and the file is ready.

## Step 2: Type in WORK 1

This is the four-step blink, written out the long way, inside a loop that runs it three times. Red, half a second on, half a second off.

Find the `# WORK 1` comment. The `for` line is already there. Type these four lines where the `pass` line is, then delete the `pass` line:

```
sb.light_both_leds(1, 0, 0)
time.sleep(0.5)
sb.light_both_leds(0, 0, 0)
time.sleep(0.5)
```

Run it. Both lights blink red three times, then the whole thing starts over, because of the `while` loop around it.

## Step 3: Type in WORK 2

Now the same blink, but driven by names instead of bare numbers, and run with a single call.

Find the `# WORK 2` comment and type this underneath it:

```
on_time  = 0.5
off_time = 0.5
red = 1
green = 0
blue = 0

blink(3, on_time, off_time, red, green, blue)
```

Then change the five numbers to whatever you want. Pick a color. Pick a speed. The `blink()` line does not change — only the values above it do.

Run it. You should see your WORK 1 blink, then your own blink right after it.

## Step 4: Type in WORK 3

This is the payoff, and it is the shortest step in the project.

Find the `# WORK 3` comment. Give those same five variables new values — a different color, a faster or slower blink. Then call `blink()` again with a line that is character for character identical to the one in WORK 2:

```
blink(3, on_time, off_time, red, green, blue)
```

Two calls that look exactly the same, doing two different things, because the variables changed in between. That is what a variable is for.
